# /zsdocs-research — Step 1: Deep research

Step 1 of the ZarishDocs workflow: validate the app idea with deep research before anything gets built.

The essentials (self-contained — no external files needed):
- Ask the user their technical level: A) Vibe-coder, B) Developer, C) In-between.
- Ask the questions for that level ONE at a time and wait for each answer — never dump the whole question bank at once. Cover: idea in plain words, who it's for, the problem and what they do today, 3-5 must-have features, platform (web/mobile/desktop), budget, timeline, deal-breakers (phrase per level).
- Echo back a short verification summary of your understanding before writing anything.
- Run your own web research (competitors, technical approaches, cost estimates, similar projects). Prefer official sources; label anything uncertain as "Unverified — model knowledge".
- Write the output to `docs/research-[AppName].md` under these headings: Project name, Core concept, Target users, Technical decisions, Competitor insights, Budget/timeline.
- End the doc with a `## Handoff Context` block (Stage: research) so the next stage skips re-asking.

Done? Point the user to the next stage: `/zsdocs-prd`.
